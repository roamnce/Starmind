Problem: Three modules for gesture handling, all shallow — interfaces nearly as complex as implementations. They add indirection without hiding complexity.

Problem: 1337 lines copied from Flutter SDK with custom gesture handling mixed in. 17 fields in State class for gesture tracking. No seam for swapping gesture behavior.

Solution: Extract gesture state machine into NavigationGestureHandler. Reduce State fields from 17 to 1.

  • Testability: gesture logic testable without widget lifecycle
  • Locality: gesture bugs found in one place
  • Leverage: other widgets can reuse gesture handling

PdfViewportController: tighten or accept as coordinator

Speculative recently refactored
lib/src/pdf/pdf_viewport_controller.dart (152 lines)

Problem: Facade exposes sub-modules publicly (session, transform, selection). Callers reach through: controller.session.getCachedPageChars(), controller.transform.panOffset, etc.

Context: Recently refactored from pass-through wrapper. Does provide coordination value (selection clearing on doc load, shared undo stack). Porous interface defeats facade pattern.

Deletion test: Deleting would force callers to manage coordination themselves. It earns its keep as a coordinator, just not as a true facade.

  • Option A: Tighten — make sub-modules private, add delegation methods
  • Option B: Accept — document that this is a coordinator, not a facade
