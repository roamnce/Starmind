# v15.1 Enhancement Plan

## Overview

This document outlines the enhancements for v15.1, focusing on two main improvements:

1. **Horizontal Floating Context Menu** - Replace the current bottom sheet menu with a horizontal floating menu using Forui library
2. **Summary Bracket Direction Fix** - Fix the issue where summary brackets appear on the wrong side for left-side nodes in bidirectional layout

---

## 1. Horizontal Floating Context Menu

### Current State

The current implementation uses `showModalBottomSheet` to display a vertical list of menu options:

```dart
// lib/src/mindmap/ui/mindmap_page.dart:1121
void _showNodeContextMenu(BuildContext context, Note note) {
  showModalBottomSheet(
    context: context,
    builder: (context) {
      // ... vertical list of ListTiles
    },
  );
}
```

**Problems:**
- Bottom sheet appears from the bottom of the screen, far from the node
- Requires extra travel distance for user's cursor/finger
- Not optimal for desktop right-click interaction

### Target State

Use Forui's `FPopoverMenu` to display a horizontal floating menu near the node:

```dart
FPopoverMenu(
  autofocus: true,
  menuAnchor: Alignment.topRight,
  childAnchor: Alignment.bottomRight,
  menu: [
    FItemGroup.group(
      children: [
        FItem.item(
          prefix: const Icon(FLucideIcons.plus),
          onPress: () => _addChildNode(),
        ),
        FItem.item(
          prefix: const Icon(FLucideIcons.arrowRightLeft),
          onPress: () => _addSiblingNode(),
        ),
        FItem.item(
          prefix: const Icon(FLucideIcons.x, color: Colors.red),
          onPress: () => _deleteNode(),
        ),
      ],
    ),
  ],
  builder: (_, controller, _) => // trigger widget
)
```

### Menu Buttons

| Icon | Action | Description |
|------|--------|-------------|
| `+` | Add Child Node | Creates a new child under selected node |
| `↔` | Add Sibling Node | Creates a new sibling node |
| `×` | Delete Node | Deletes the selected node (red color) |

**Note:** No text labels, only icons.

### Smart Positioning

The menu position should be determined by the node's position on the canvas:

```dart
// Determine menu anchor based on node position
final nodePosition = positions[note.id];
final isOnRightSide = nodePosition != null && nodePosition.dx >= 0;

// If node is on right side, show menu on left (to avoid going off-screen)
// If node is on left side, show menu on right
final menuAnchor = isOnRightSide ? Alignment.topLeft : Alignment.topRight;
final childAnchor = isOnRightSide ? Alignment.bottomLeft : Alignment.bottomRight;
```

### Implementation Approach

1. **Add Forui dependency** to `pubspec.yaml`
2. **Create a new widget** `NodeContextMenu` that wraps the node with `FPopoverMenu`
3. **Modify `NodeWidget`** to integrate the context menu directly
4. **Remove `_showNodeContextMenu`** method from `mindmap_page.dart`
5. **Update trigger mechanism:**
   - Desktop: Right-click (`onSecondaryTap`)
   - Tablet: Long-press (`onLongPress`)

### Files to Modify

| File | Changes |
|------|---------|
| `pubspec.yaml` | Add `forui` dependency |
| `lib/src/mindmap/ui/node_widget.dart` | Integrate `FPopoverMenu` |
| `lib/src/mindmap/ui/mindmap_page.dart` | Remove `_showNodeContextMenu`, pass position info to NodeWidget |

## 2. Summary Bracket Direction Fix

### Current State

The summary bracket direction is calculated using average position:

```dart
// lib/src/mindmap/ui/mindmap_page.dart:556-558
} else if (widget.controller.layoutDirection == LayoutDirection.bothSides) {
  // 两侧布局：根据被覆盖子节点的平均位置判断
  isRightward = coveredCount > 0 && (coveredCenterX / coveredCount) >= 0;
}
```

**Problem:** When a summary covers multiple nodes, the average position might be misleading. For example:
- 3 nodes on left (x = -200, -180, -160)
- 1 node on right (x = 100)
- Average: (-200-180-160+100)/4 = -110 → bracket goes left (correct)
- But if right node is at x = 500: (-200-180-160+500)/4 = -10 → bracket goes left (wrong!)

### Target State

Use majority vote to determine bracket direction:

```dart
} else if (widget.controller.layoutDirection == LayoutDirection.bothSides) {
  // 两侧布局：根据被覆盖子节点的多数位置判断
  int leftCount = 0, rightCount = 0;
  for (int i = summary.startIndex; i <= endIdx; i++) {
    final pos = positions[childIds[i]];
    if (pos != null) {
      if (pos.dx < 0) leftCount++;
      else rightCount++;
    }
  }
  isRightward = rightCount >= leftCount;
}
```

### Logic

| Scenario | Left Count | Right Count | isRightward |
|----------|------------|-------------|-------------|
| All nodes on left | 3 | 0 | false (left) |
| All nodes on right | 0 | 3 | true (right) |
| 2 left, 1 right | 2 | 1 | false (left) |
| 1 left, 2 right | 1 | 2 | true (right) |
| Equal split | 2 | 2 | true (right, default) |

### Files to Modify

| File | Changes |
|------|---------|
| `lib/src/mindmap/ui/mindmap_page.dart` | Update `isRightward` calculation logic |

## Implementation Order

1. **Task 1: Add Forui dependency**
   - Add `forui: ^latest` to `pubspec.yaml`
   - Run `flutter pub get`

2. **Task 2: Fix summary bracket direction**
   - Update the `isRightward` calculation in `_buildCanvas`
   - Test with bidirectional layout

3. **Task 3: Create NodeContextMenu widget**
   - Create new file or integrate into NodeWidget
   - Implement smart positioning logic

4. **Task 4: Integrate context menu into NodeWidget**
   - Wrap node content with `FPopoverMenu`
   - Pass position information for smart anchoring

5. **Task 5: Remove old bottom sheet code**
   - Delete `_showNodeContextMenu` method
   - Clean up unused imports

6. **Task 6: Testing**
   - Test right-click on desktop
   - Test long-press on tablet
   - Test menu positioning at canvas edges
   - Test summary bracket direction in all layouts

- **Forui**: `^0.6.0` or latest
  - Documentation: https://forui.dev/docs
  - Based on shadcn/ui design principles
  - Provides `FPopoverMenu`, `FItem`, `FItemGroup`, `FLucideIcons`

## Success Criteria

1. Right-clicking a node shows a horizontal floating menu with 3 icon buttons
2. Menu appears on the appropriate side based on node position
3. Summary brackets in bidirectional layout always point in the correct direction
4. No text labels in the context menu (icons only)
5. Desktop and tablet interactions work correctly
